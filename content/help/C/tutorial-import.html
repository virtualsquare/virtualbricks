Import a lab without its image

A colleague sends you DTN2hops_26_Feb_2026.vbp, a lab of four virtual machines, node1 to node4, five switches, a switch wrapper and three channel emulators. The machines run on private copies of one disk image, debian13, a file of a few gigabytes that the archive doesn't hold: the private copies are in it, with what was done in each machine, but not the image they are made on. Your colleague sends the image apart, or you have it already.

The lab was made with Virtualbricks 2.1, and Virtualbricks converts it while it reads the archive. An archive of this version imports the same way.

Open the archive

  1. Choose Projects ▸ Import…, or Import… in the Projects window. The Import Project window asks for the archive.

  2. Click the button of the file, which says (None), and choose DTN2hops_26_Feb_2026.vbp. The window reads the archive, then shows what it holds.

The Import Project window, with the lab

What the window offers

Name

DTN2hops_26_Feb_2026, the name of the file. If a project has it already, the window suggests DTN2hops_26_Feb_2026-2: an import never replaces a project. You can change it.

The bricks

Below the name, how many bricks of each kind the project has, by the names of the project file: netemu are the channel emulators, qemu the virtual machines.

Images

A row for debian13, used by the disk hda of each of the four machines, with three choices:

  • Copy, from the archive to the shared images of your workspace;

  • Use a file… of this computer;

  • Leave unset, for its disks to get an image later.

Leave unset is chosen: the window looked for the image where the project had it, /home/carlo/VB_images/debian13.qcow2 on your colleague's computer, and in your shared images, under the name debian13.qcow2, and found it in neither. Had it found it, Use a file… would be chosen, with that file.

Open the project after the import

On: once imported, the lab opens in the main window.

What is grey, and why

Copy

The archive doesn't hold the image: there is nothing to copy. Its tooltip says Not in the archive. In a large archive, the window may look for the image for a while: Copy is chosen meanwhile, the row says Looking in the archive…, and Copy turns grey once the window has read the archive to its end.

Import

Grey until the window has read the archive, and whenever something stops the import; the window says what. Under the name: a name that is empty, has a /, starts with a dot, is too long, or is a project's already. At the bottom, in red: a file chosen with Use a file… that isn't there any more, or a name too long for the names of the bricks. Their sockets are in a folder named after the project, and the path of a socket has at most 107 bytes; the longest name of this lab, sat_channel_emulator, has 20.

This computer's paths

Not there at all for this lab. It shows when the project names the folders of QEMU and VDE of the computer it comes from, and they aren't yours; a project of Virtualbricks 2.1 doesn't name them.

Projects ▸ Import…

Grey in the windows of another Virtualbricks, opened with --connect: the archives stay on the computer they are on, for now. See Another computer.

Choose the image

This is the choice that matters.

You have the image

Click Use a file… and choose it; the row then says Uses and its path. The import points the private copies of the four machines at it, so that they keep what was done in them. It must be the image the lab was made on, a copy of your colleague's file: a private copy holds only the changes over its image, and over another one the machine finds a damaged disk.

You don't have it

Keep Leave unset. The project comes without the image debian13, and the disks of the four machines without an image. Their private copies come as the archive has them, made on the file of your colleague's computer. When you give the disks an image, in their settings, the first start of each machine moves its private copy aside, as node1_hda.cow.bak- and the date, and makes a new one, empty: the machine starts from the image as it is, without what was done in it.

If you get the image later, import the archive again then, with Use a file…, and remove the first import.

Import

  1. Click Import. The window shows the progress, and Cancel becomes Stop: an import stopped removes what it wrote. You can close the window, and let the import finish.

  2. The main window shows DTN2hops_26_Feb_2026, with its thirteen bricks, all stopped.

  3. Open File ▸ Logs: the import says what needs your attention. With the image left unset: left unset: give its disks an image in their settings, and for each machine its image is unset, the private disk is left as it is.

If a brick of the project open before runs, the lab is imported but doesn't open: stop the bricks, then open it from the Projects window.

In the Bricks tab, the start button of switchwrapper is grey: a switch wrapper is a switch that another program runs, at /var/run/switch/sck, and it runs while that program's switch is there. See The kinds of brick.
