The terminal command

The setting terminal names a program, and a console opens as terminal -e program socket, so only a terminal that takes -e that way can open it. This page makes the setting a command line with a place for the console, {command}, so that any terminal works, with its own options: gnome-terminal -- {command}, xfce4-terminal -x {command}, xterm -hold -e {command}.

§1At a glance

Setting
A command line, split into words as the shell splits them and run without a shell; {command} stands for the console, vdeterm or unixterm and the socket, and {name} for the brick, as in xterm -T {name} -e {command} (§3, T1, T5).
Before
A value without {command} runs as today, with -e {command} after it: xterm, the files that develop wrote, the term of 2.1 and its events keep working, with no migration (§4, T1). The default shows the form: x-terminal-emulator -e {command} (T4).
In a word
{command} inside a longer word or in quotes gives the console as one word, quoted for the shell, for a terminal that takes one string: foot sh -c '{command}; read' keeps the window open once the brick stops (T2).
Menu
The lines of the known terminals that this computer has, each in its own form, checked on the seven targets: gnome-terminal -- {command}, terminator -x {command} (§5, T3).
Checks
A quote that isn’t closed is refused, in the window, the console and the files; a program that isn’t found is a warning, as today (§6).
Plan
Two steps: the setting and the consoles, with the check of the targets; then the window, the guide and an end-to-end scenario (§7).

§2Today

  • Brick.open_console() (bricks/__init__.py:712) runs [terminal, "-e", which(term_command), console()]: vdeterm on the control socket of a switch and the other VDE bricks, unixterm on the monitor of a machine.
  • The windows of --connect open the consoles of the bricks there with the terminal of this computer: Consoles.open() (remote/tunnel.py:346) runs the same line on a socket of their own, which they join to the console there (page 19 R8).

§3The setting

  • The value is a command line. Its words are split as the console splits its lines, shlex.split() (console/parser.py): quotes keep spaces, a backslash escapes. No shell runs it, so no variables and no pipes, unless the line runs a shell itself.
  • {command} typed as a word of its own, outside quotes, becomes the words of the console: the program, with its path, and the socket.
  • {command} inside a longer word or in quotes becomes those words quoted for the shell, shlex.join(), as one word, for a terminal or a shell that takes the command as one string (T2 A). Quotes make one word, as in the shell: '{command}' is one.
  • A value without {command} gets -e {command} at its end, which is what Virtualbricks does today (T1 A).
  • {name} becomes the name of the brick, for the title of its window; over a connection, the name of the brick there (T5 B). As a word or inside one it is the same text, since a name holds only letters, digits, _, - and ..
  • Braces elsewhere stay as they are typed: the line isn’t a format string of Python.

One function makes the line, terminal_command(setting, command, name) in bricks/__init__.py, beside TermProtocol, which remote/tunnel.py imports already. Brick.open_console() and Consoles.open() both call it, so a console opens the same way over a connection. The log line Opening console for sw1 shows the line that runs, as now.

§4The values of before

With T1 A, every value of before means what it meant, since a value without {command} gets today’s -e:

  • terminal = "x-terminal-emulator", in the settings.toml that develop wrote since page 23. It loses its # default mark when the default becomes x-terminal-emulator -e {command} (T4 A), and opens the same console.
  • The term of 2.1, a path such as /usr/bin/xterm, which migrate/convert.py renames to terminal and checks as a file (convert.py:270). 2.1 ran it as one word, so it holds no spaces; the check stays.
  • A 2.1 event that ran config set terminal /usr/bin/xterm, which the migration turns into setting set terminal=/usr/bin/xterm.
  • A value typed in the console, as setting set terminal=xterm.

The other answers to T1: B adds a table of forms by the program’s name, so that gnome-terminal alone gets --. It is kinder to a name typed by hand, but the setting then means three things, a line, a known name, or another name with -e, and the menu of §5 already writes the right line. C keeps the setting a program and only that table, so options and unknown forms stay impossible. D makes {command} required and rewrites the old values; with the files unreleased since page 10 that is allowed, but it gains nothing over A and breaks setting set terminal=xterm in scripts and 2.1 events.

§6The checks

  • A quote not closed can’t open a console. The field gets a kind of its own, Command in config/schema.py, a Str whose check splits the words: the Settings window marks the row as an error, as for any value its kind refuses; setting set refuses it, saying that a quote isn’t closed; and the reader of settings.toml reports it and keeps the default, as for any bad value.
  • A program not found, the first word, stays a warning of the row, as _check_terminal() gives it today: the line is right, the computer lacks the program.
  • No terminal, an empty value, stays the warning it is.
  • No {command} is no problem: the value runs with -e (§4).

A console that can’t open for another reason is told as today: the console says why (brick monitor), and the windows log it (brickmenu.console()).
