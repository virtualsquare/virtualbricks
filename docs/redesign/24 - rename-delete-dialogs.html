Virtualbricks Rename and Delete

The dialogs that rename a brick, an event or an image, and delete a brick or an event, take the form of the newer ones: a header bar with Cancel and the action, the reason under the field, and, before a delete, what goes with it. A delete also clears what names the item, and a machine’s private copies go with it, after a line that says so.

§1At a glance

Rename
A dialog like Rename Project. The header bar says Rename Brick, Rename Event or Rename Image over the name. The field holds the name, selected, and under it a line says why a new name can’t be used, or what it becomes. A refusal keeps the dialog open with the reason (R1).
Delete
One dialog for a brick and an event, like Remove Image: Delete the brick sw1?, then what goes with it, and Cancel and a red Delete instead of No and Yes (D1).
Names
A delete clears what names the item: the actions of events that start or stop it, and When It Starts and When It Stops of the bricks that run it. The dialog lists them. The console’s brick delete and event delete do the same (D2).
Running
A running brick has Delete… greyed in its menu, as Rename… is, and the Delete key does nothing on its row. A waiting event stops and goes, as today (D3).
Copies
A machine’s private copies go with it, to the trash or, without one, for good, and the dialog says so in a line. Today they stay in the project folder, and a new machine of the same name starts from them (D4).
Code
renamedialog.py is rewritten; deletedialog.py replaces confirmdialog.py. The factory’s remove_brick() and remove_event() clear the references, found by a new users() that the dialog reads too. The protocol doesn’t change (§6).

§2Today

These pictures are the dialogs of f7156ee on Broadway, with Cantarell 11 as on your desktop, in a project with a switch sw1, a machine vm1 and a wire w1 plugged into it, and an event lab_start that starts both. The delete dialogs have no title, so the window shows the name of the program, here my script’s.

What I found, each one checked:

  1. Rename says “brick” for everything. The title is Virtualbricks - Rename brick and the empty field says Brick name, for an event and an image too. The label says Chose a new name.
  2. The name isn’t selected. build_ui() gives the field the focus, and __init__ sets the name after, so the cursor stands before the name and what you type goes in front of it. Rename Project selects the name, so typing replaces it.
  3. Why a name can’t be used is only in a tooltip, behind a red frame. The words are the factory’s: Normalized name vm1 already in use, Name must contains only letters, numbers, underscores, hyphens and points.
  4. Spaces become underscores without a word. normalize_name() turns lab sw into lab_sw, which is a valid name, and the dialog doesn’t say so.
  5. A refusal closes the dialog. A name refused goes to the Messages window as Invalid name core, without the reason; the dialog checks with the factory that renames, so that happens when the name is taken between the check and OK. A machine’s private copies are renamed with it, and a folder that refuses raises an OSError, which _refused() doesn’t trap: it ends as an unhandled error in a Deferred.
  6. No margins. The label and the field touch the sides of the window, and Cancel and OK fill the bottom, as Glade packed them.
  7. Delete asks “Do you really want to delete sw1 (Switch)?” with No and Yes, and says nothing of what goes with it. Deleting sw1 unplugs vm1 and w1. The event lab_start keeps its action that starts sw1: its editor marks it sw1 (missing), and when the event runs the action fails with No brick or event named sw1.
  8. An event deleted stays named by the bricks that run it. A brick whose When It Starts is lab_start logs The Event lab_start attached to Brick vm1 is not available at each start, and the next open of the project warns bricks.vm1.on_start: no event named "lab_start".
  9. A running brick can be asked to go. Delete… is in its menu, and the Delete key works on its row. After Yes the factory refuses, and the Messages window says Cannot delete brick vm1: brick is running.
  10. A machine’s private copies stay in the project folder as vm1_hda.cow. A new machine named vm1 with a private disk of the same image starts from that copy, with the old machine’s changes: _ensure_private_image_cow() keeps a copy whose backing file is the image. With another image, the copy is moved to a .bak- file, and stays too. The TODO’s item about renaming a machine safely names these files as what a rename can overwrite.
  11. The waiting event is stopped and deleted, which is right, but the dialog says The event is in use, it will be stopped before.

§4Delete

One dialog for a brick and an event, Remove Image’s (D1): the title, Cancel and a red Delete in the header bar; the question in bold; then a line for each thing that changes with it. Delete is the destructive action and not the default, so Enter doesn’t delete; Esc cancels. The lines, in this order:

  1. the bricks plugged into it, which will be plugged into nothing: vm1 (eth0) and w1 will be plugged into nothing. A machine is named with its card, as its summary does;
  2. the events that start or stop it, which lose those actions (D2): The event lab_start loses its action that starts sw1.;
  3. for an event, the bricks that run it when they start or stop, and lose it: vm1 will no longer run it when it starts.;
  4. with none of these, Nothing else uses it.;
  5. for a waiting event: It is waiting: it stops, and its actions don’t run.;
  6. for a machine with private copies, that they go, with their names and size (D4).

A running brick never gets the dialog (D3, board G). If it starts while the dialog is open, the factory refuses the delete, as it does now, and the Messages window says why. The bricks’ own plugs aren’t listed: the wire w1 deleted leaves sw1 and sw2 as they were, with a free port more.

Over a connection the lines come from the bricks and events the windows mirror, which have the links, the actions and the settings, so they are the same. The size of the private copies is asked of the lab machine first, as Remove Image asks of its file: the line shows once the answer is there, and Delete waits for it. The copies go to the lab machine’s trash, if it has one.

§5Other directions

Two more, without a board. D1 C: ask only when something else changes, and delete at once a brick that nothing uses. The Delete key would then sometimes ask and sometimes not, and a machine’s settings are lost either way. D3 C: for a running brick, a red Stop and Delete that stops it and deletes it once stopped. Stopping a machine powers it off without asking its system, so it’s a second destructive step in one click.

§6The code

What names an item

A new function finds what loses an item when it goes, and both the factory and the dialog use it. In brickfactory.py, beside remove_brick():

remove_brick() disconnects the plugs, as it does now, and drops the actions; remove_event() drops the actions and sets the settings to "" through update_config(), so the panels and the lab machine’s windows learn it. Each change is logged as the plugs are today. The console’s brick delete and event delete go through the same functions, so virtualbricks(1) says what they clear, as it does for event rename.

The dialogs

  • gui/dialogs/renamedialog.py: RenameDialog(engine, item) rewritten on Rename Project’s pattern: check() as you type, with the factory’s check_name() or check_brick_name() as now; normalize_name() for the line of board B; the refusal of engine.rename() shown in the dialog, an OSError of the private copies included, with the file’s name and the reason.
  • gui/dialogs/deletedialog.py: DeleteDialog(engine, item) for a brick and an event, and uses_words(users) for the lines, as disks_words() is for an image. For a machine, Delete calls engine.start_over(vm, device) for each private copy that is there, the call Start Over makes, then engine.remove(vm); a copy that can’t go is logged, and the machine is deleted anyway. No new engine call, and no new AMP command. The console’s brick delete leaves the copies, as now (§10).
  • brickmenu.py: update() enables delete only while the brick doesn’t run. rowtab.py: the Delete key activates the row’s action, as F2 does, if it is enabled, instead of calling remove(); the tabs name the action, since the Images tab’s is remove.
  • confirmdialog.py goes: its two dialogs are its only users. The main window’s ask_remove_brick() and ask_remove_event() open DeleteDialog.
  • _dialog() and _label() move from imagedialogs.py to gui/dialogs/base.py, as action_dialog() and label(), for the image dialogs and these two.
