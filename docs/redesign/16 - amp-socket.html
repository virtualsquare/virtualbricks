§1At a glance

Option
--socket opens the text socket at $XDG_RUNTIME_DIR/virtualbricks/.control. --socket unix:PATH:protocol=amp opens an AMP socket at PATH. The description follows Twisted’s endpoints, with one more keyword, protocol: text, the default, or amp. The option can be given more than once (M1, M8).
Default
Without --socket, Virtualbricks listens nowhere. Today every Virtualbricks listens, so this changes Q1 of page 15.
Types
unix only, for now. tcp and ssl, on this machine and across the network, come later (M6). A path without unix: is refused, with a message that shows how to write it (M7).
Owner
Each socket has its own lock, PATH.lock. The first Virtualbricks that takes it listens there, and the others go without that socket. Each socket goes on its own: when one can’t be opened, the others still listen.
Commands
Two AMP commands. Hello says who answers: the protocol, the version, the process and the open project. Run takes a line of the console and answers its lines (M2).
Errors
A command that fails raises CommandFailed in the program, with the console’s message (M3). An answer too long for AMP raises AnswerTooLong, and the connection stays open (M5).
Order
The requests of a connection run one after the other, as on the text socket. Connections don’t wait for each other (M4).
--command
It talks to the text socket at the default path, or to the one that --socket names. It speaks only the text protocol.
Definitions
virtualbricks.console.ampwire holds the two commands and their errors, and loads no reactor. A program imports it, or copies its twenty lines from the manual page.
Plan
Three steps, a commit each, on a new branch mg/amp-socket from develop (§8).

§2Today

Page 15 made the control socket: JSON Lines on .control, spoken by virtualbricks --command, by socat and by any language. This page calls its protocol the text protocol. Every Virtualbricks listens there once its project is open (15 Q1). --socket PATH moves the socket to a path, for both ends: the Virtualbricks that listens, and --command, which talks to it. The lock is PATH.lock.

A program written with Twisted can speak the text protocol too, but it has to do by hand what AMP does for it: a LineOnlyReceiver, the JSON of each line, each answer matched to its request by their order, and ok: false turned into an error.

AMP is Twisted’s own protocol, twisted.protocols.amp. A request is a box of keys and values with a tag, and its answer carries the tag back. Each value holds at most 65 535 bytes. callRemote returns a Deferred of the answer, and an error that the command declares arrives as its exception. UNIXClientEndpoint connects to a Unix socket.

Every socket leads to the same place: dispatch.run(), with the commands of the console, their checks, and the cwd of the request (15 Q6). The AMP socket adds a way in. It doesn’t add any command.

§3The option --socket

With a description or without

  • Without --socket, Virtualbricks listens nowhere and takes no lock of a socket (Q1 of page 15 changes).
  • --socket alone opens the text socket at the default path, $XDG_RUNTIME_DIR/virtualbricks/.control.
  • A description is the next word, or comes after = (M8). The next word is taken when it starts with a type and a colon, such as unix: or tcp:. Any other word isn’t taken: --socket --no-gui is --socket alone, and so is --command --socket brick list. A path isn’t a description: --socket ~/labs/lab1.sock is refused with a message that shows unix:~/labs/lab1.sock (M7).
  • Before getopt. Twisted’s option parser uses getopt, which has no optional arguments. So parseOptions takes each --socket and its description out of the arguments before getopt reads the rest. It stops where getopt stops: at the first word that isn’t an option or the value of one, or at --.

The description

  • The type comes first. It is unix, the only one for now. tcp and ssl are known, and refused until they come (M6).
  • The path comes next, or address=PATH, as Twisted writes it. Virtualbricks expands ~, since the shell doesn’t expand it after unix:. A relative path is read from the folder where Virtualbricks starts.
  • The protocol is protocol=text or protocol=amp, in any case. Left out, it is text.
  • Escapes. : separates the parts, and \ makes the next character plain, so unix:/tmp/a\:b.sock is the path /tmp/a:b.sock. The shell removes a backslash that isn’t quoted, so such a description goes in single quotes. In a key=value, only the first = counts. These are the rules of Twisted’s _tokenize and _parse. Those are private, so Virtualbricks has its own parser that follows them, in console/wire.py.
  • No other keyword. Twisted’s mode, backlog and lockfile are refused. The socket is always 0600, and its lock is Virtualbricks’ own.

Several sockets

The option can be given more than once, and Virtualbricks listens on each socket. This is how both protocols are open at once: --socket --socket unix:~/labs/lab1.amp:protocol=amp is the text socket at its default path and an AMP socket. The same protocol twice is fine, such as a text socket in the runtime folder and another in ~/labs. The same path twice is refused, and so is --socket alone twice.

Who has each

Each socket has its own lock, PATH.lock beside it, as --socket PATH has today. The first Virtualbricks that takes the lock listens there. Another one goes without that socket, and logs which process has it. With --lock none, two Virtualbricks started with the same options leave every socket to the first one. Started with different --socket options, each has its own.

Each socket goes on its own. When one can’t be opened, because its lock is held, something else is at its path, or its folder fails a check, the others still listen, and the log says why. The rest is as on page 15: a socket of yours left behind by a crash is removed, the mode is 0600 from the start, and at the end each connection is closed after its last answer, the socket removed and its lock released.

Checks

A path in the runtime folder gets the checks of the default socket: the folder must be yours, and nobody else can write in it. The folder may not exist yet when the options are read, since Virtualbricks makes it at start. Anywhere else, the folder must exist, as today. Each path can have at most 107 bytes, the most a Unix socket path can have, and that is checked with the other options.

With --command

--command speaks the text protocol. It talks to the socket at the default path, or to the one that --socket names; --socket alone is the default path, as no --socket is. It takes at most one --socket, and that socket must use the text protocol. Since a Virtualbricks started without --socket listens nowhere, the messages of --command that find nobody say to start it with --socket (§6).

§4The protocol

Two commands (M2), as Twisted declares them. This is the whole contract: a program needs these lines and nothing else of Virtualbricks.

CommandKeyWhat it is
Helloprotocol1. It changes on the day a command changes.
versionThe version of the Virtualbricks that runs.
pidIts process.
projectThe name of the open project, None when none is open.
RunlineThe command, as typed in the console.
cwdThe folder that paths are read from, an absolute path. It is optional; without it, the folder of Virtualbricks (15 Q6).
linesThe answer.
errors of RunCommandFailedThe message, in the language of the Virtualbricks that runs (M3). A cwd that isn’t absolute gets it too, with the message of the text socket.
AnswerTooLongThe command was done, but its answer is longer than a value of AMP can be (M5).
UnhandledCommandAMP’s own, for a command that this Virtualbricks doesn’t know.
  • No greeting. AMP has none. A program calls Hello when it needs to know who answers.
  • Versions. When a command has to change, the new one gets a new name and Run stays as it is, so a program written today keeps working. An older Virtualbricks answers a newer command with UnhandledCommand, and protocol tells the program which commands it can use.
  • Order. The requests of a connection run one after the other: a second callRemote waits for the answer to the first. A program that sends brick start sw1 and then brick start vm1 without waiting gets them in that order. For two commands at once it opens two connections (M4). Connections, the text socket, the terminal and the events don’t wait for each other (15 Q7).
  • Limits. A value holds at most 65 535 bytes. A longer line is refused by the program’s own AMP before it is sent, as the text socket refuses a line over 64 KiB. The answer is one value, a list of lines. brick list of a large project fits many times over, but a long source could go past it. AMP would then drop the connection and log a traceback; instead, Run fails with AnswerTooLong and the connection stays open (M5).
  • Bad boxes. A box that doesn’t fit Run, such as one without line, is left to AMP. AMP answers with an unknown error and closes the connection. A program that uses the definitions above can’t send one.
  • The log. AMP logs each connection that opens and closes, with the addresses of its objects. The AMP socket leaves that out, as the text socket’s factory does since fd789ad.

§5A program

For a Virtualbricks started with --socket unix:~/labs/lab1.amp:protocol=amp:

  • Where Virtualbricks isn’t installed, the program copies the definitions of §4 in place of the import.
  • With cwd=os.getcwd(), source lab.vb reads the lab.vb of the program’s folder, as --command does.
  • When nothing listens, connectProtocol fails with ConnectError.
  • --command connects only to a socket that belongs to you. A program that connects to a path in a folder that others can write to, such as /tmp, should check the same.

§7The code and the tests

  • The description. wire.parse_socket(text) returns a Socket, its path and its protocol, or raises ValueError with the message of §6. It follows Twisted’s tokenizer, with no Twisted, like the rest of wire.py. It knows tcp and ssl to refuse them, and the rest of the code keeps the type, so that they can come later. wire.TEXT and wire.AMP name the protocols.
  • The option. Options.parseOptions takes each --socket out of the arguments before getopt. It knows which options take a value, so their values aren’t taken for words, and it stops at the first word or at --. Each description is parsed, ~ expanded, the path made absolute and checked, and the socket appended to config["sockets"], which stays empty without the option. --help still lists --socket. check_command refuses an AMP socket, or two sockets, with --command.
  • The server. control.listen(brickfactory, socket, reactor) listens on one socket: its checks, its lock, its stale socket and the factory of its protocol. Application.listen calls it for each socket of config["sockets"], and for none without the option. Control stays one per socket.
  • The client. client.main gets the path of the one text socket, or the default path. Its messages that find nobody say to start Virtualbricks with --socket.
  • AMP. ampwire.py has PROTOCOL, the two errors and the two commands, and imports only twisted.protocols.amp; the manual page shows it whole. AMPControl(amp.AMP) in control.py answers Hello and Run. Run goes through the queue of its connection to dispatch.run() with its cwd, as a line of the text socket does, and measures the answer before AMP writes it. It leaves out AMP’s log of each connection.
  • What both protocols share. The queue of ControlProtocol, its requests, busy and next(), moves into a small class that both use. ControlFactory takes the protocol it builds. wire.check_cwd() is the check of read_request, moved out so that both sockets give the same message.

§9Decisions

QuestionOptionsDecided
M1 Where the AMP socket is

Revision 1 proposed .control.amp beside .control, under one lock. Your answer replaces it: each socket is where a --socket description says, with its protocol and its own lock. --socket alone is the text socket at its default path, and without the option there is no socket (§3).

 your answer
M2 The commands of the AMP socket

A Two: Hello, who answers, and Run, a line of the console and its answer. Every command of the console works through Run, as through the text socket, and the protocol doesn’t change when the console does.

B One AMP command for each command of the console, made from its table, with typed arguments: BrickStart(names=[...]), BrickSet(name=..., values=...). That makes about fifty commands to keep stable, and each change to the console changes the protocol.

 A; B later
M3 A command that fails

A The program’s Deferred fails with CommandFailed, whose text is the error. What the command did before is dropped: after a failed brick start sw1 vm1, status tells whether sw1 runs.

B CommandFailed too, but its text is what the command did before, a line each, then the error, as the console shows them. A program that wants the error alone takes the last line.

C No failure: the answer carries ok, lines and error, as on the text socket. The program checks ok after every call.

 A
M4 The requests of one connection

A One after the other, as on the text socket (15 Q7): a request waits for the answer to the one before. Two at once need two connections.

B All at once: AMP tags each answer, so a slow brick start doesn’t hold up a status sent after it on the same connection. A program that needs an order waits for each answer.

 A
M5 An answer longer than AMP carries, 64 KiB

A Run fails with AnswerTooLong, which says that the command was done, and the connection stays open. A text socket carries any answer.

B An argument type of our own spreads a long answer over several keys, lines, lines.2 and so on. Nothing is lost, but every program needs that class too.

C The answer is cut at 64 KiB, with a last line that says how much is missing.

 A
M6 The types of socket

A unix only. The mode 0600 and the checks of the folder keep everyone but you and root out. Anyone who connects can run a shell command as you, through an event’s actions.

B unix, and tcp on 127.0.0.1 only. Every user of the machine can then connect and run commands as you, so it needs a password or a token first.

C Every type that Twisted knows: tcp, ssl, systemd and the plugins. This means serverFromString in place of our own listenUNIX, and the checks and locks of page 15 for unix alone.

 A for now; tcp and ssl later
M7 A path without unix:

A Refused, with a message that shows the same path with unix: before it. There is one form, and a path with a colon in it can’t be read two ways.

B Read as unix:PATH of the text protocol when it starts with /, ~ or ., as --socket PATH is read today.

 A
M8 How --socket takes its description

A The next word, when it starts with a type and a colon, such as unix:, or after =. Any other word isn’t taken, so --socket --no-gui is --socket alone.

B Only after =, as the optional arguments of GNU tools, such as ls --color[=WHEN]. With a space, the description is left as a stray word, and the message says to write --socket=.

 A

Your answers, 29 September. On revision 1: --socket takes a syntax like that of twisted.internet.endpoints._parseServer, extended with the protocol, text (the default) or AMP; without the option, the text protocol uses the default path. On revision 2: without --socket no socket is open; --socket without an argument opens one at $XDG_RUNTIME_DIR/virtualbricks/.control; M6 is unix only for now, and the plan is to add tcp and ssl, local and remote; all the other suggestions are fine. M8, which your answer raised, you chose A.

Left alone, AMP drops the connection on an answer that is too long and logs a traceback. I checked this and the other behaviours of AMP on this page with Twisted 26.4, the version in .venv: an optional value arrives as None, and a declared error arrives as its own exception.
