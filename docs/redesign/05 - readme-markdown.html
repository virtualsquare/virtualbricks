§1At a glance

Syntax
A subset of CommonMark, the core that GitHub, GitLab and most editors share: headings, bold and italic, code, lists, quotes, links and rules. Anything else, as a table or an image, stays as you typed it.
Where
Rendered where the README is only read: the details of the Projects window and the Import dialog. The Readme tab opens on the rendered README; two icon buttons floating at its top right switch to the plain text editor and back. The New Project dialog stays as it is.
File
Still README, still plain text: nothing changes on disk, in archives or in the migration. A README written before reads the same, line by line (M3).
Code
markdown-it-py, a CommonMark parser in pure Python that the distributions package, reads the text; a small renderer draws its tokens in a GtkTextView. No web view.

§2Markdown dialects

Markdown was a syntax page and a Perl script, with no specification, so every implementation settled the unclear cases its own way. CommonMark pinned the core down; most dialects in use today are CommonMark with extensions.

DialectWhat it isAdds to the coreUsed by
Markdown.plJohn Gruber’s original, 2004: a syntax page and a Perl script, no specification.— it is the core, loosely definedThe reference for the older implementations.
CommonMarkAn exact specification (0.31.2, 2024) with over 600 examples, and reference parsers, cmark and commonmark.js.Nothing: it settles the coreDiscourse, Stack Overflow, Matrix clients, VS Code’s preview (markdown-it), and the dialects below.
GitHub FlavoredGFM: CommonMark plus extensions, with its own specification (0.29-gfm).Tables, task lists, strikethrough, bare URLs as links, some HTML refusedGitHub, Gitea and Forgejo, most editors and note apps.

Pandoc’s MarkdownThe richest, meant for documents.Footnotes, definition lists, math, citations, four kinds of tables, metadataPandoc, which writes the manual pages of this project; R Markdown and Quarto.
Python-MarkdownGruber’s syntax in Python, with extensions; not CommonMark (a nested list needs four spaces).Tables, fenced code, footnotes, as extensionsMkDocs.
MultiMarkdown, Markdown ExtraOlder extensions of Gruber’s syntax.Tables, footnotes, definition lists, metadataSome site generators and note apps.

What renders the same almost everywhere is CommonMark; GFM is the superset most people meet. A subset of CommonMark therefore reads the same here, on GitHub and GitLab, and in any editor’s preview (M1).

What stays as you typed it

Tables, task lists, footnotes and raw HTML aren’t in the subset: they show as the text you wrote, which is still readable. A picture, ![map](map.png), shows as its text, map (M7). A line indented by four spaces stays a line of text, not code, though without its indentation.

A README written before

An old README is plain text, and stays readable rendered: every line stays a line (M3), paragraphs stay paragraphs. What changes is what already looked like Markdown: a line that starts with - or 1. becomes a list item, # a heading, > a quote, a title underlined with === a heading, and *words* italic. Underscores inside names, as vm1_hda, stay underscores.

§5Mock-ups

The windows are drawn in GTK 3’s Adwaita look, with only what a GtkTextView can draw: a quote is indented and dimmed, without a bar at its side. The same README runs through every board.

§6Rendering in GTK

The parser

markdown-it-py is the Python port of markdown-it, the CommonMark parser of VS Code and Discourse: pure Python, no compiled parts, packaged by Debian (python3-markdown-it, 3.0.0 in Debian 13), Ubuntu and Fedora, where rich depends on it. It starts from its zero preset, with every rule off, and enables fifteen: headings of both kinds, lists, quotes, fenced code, rules, emphasis, strikethrough, inline code, links, pictures, <URL> links, escapes, entities and line breaks. HTML stays off. The parser gives a flat list of tokens, which the renderer walks. Tried on this machine with markdown-it-py 3.0.0: a table and raw HTML stay text, a picture gives its text, and vm1_hda keeps its underscores (M2).

With its breaks option, a new line in a paragraph is a line break, as in GitHub’s comments. Without it, CommonMark joins the lines of a paragraph into one, which would run together the lines of the READMEs written before (M3).

The Readme tab

Two floating buttons are little work in GTK 3, about forty lines:

  • a GtkOverlay holds a GtkStack with the preview and the editor of today, each in its scrolled window;
  • over its top right corner floats a linked pair of GtkRadioButtons drawn as buttons, each with a 16-pixel symbolic icon of the Adwaita theme, document-edit-symbolic and view-reveal-symbolic, both installed here;
  • the osd style draws them on a translucent dark background, visible over the text in the light and the dark theme;
  • a right margin on both views, as wide as the buttons, keeps any line from going under them;
  • each has a tooltip and an accessible name, Edit and Preview, since it has no text; they can be reached with the keyboard like any button.

The preview is what the tab shows when a project opens; switching to it renders the text of the editor. An empty README shows, in the preview, a dimmed line saying that the pencil writes one. The third icon, the syntax, exists only in the editor (M8).

The view

A read-only GtkTextView, MarkdownView, filled from the tokens, draws everything with tags:

  • headings larger and bold; emphasis, bold and strikethrough;
  • code in the monospace font on a tinted background, a code block as a tinted paragraph with margins;
  • list items with their bullet or number and a hanging indent, nested ones further in;
  • quotes indented and dimmed;
  • links underlined in the link colour, with a hand pointer; a click opens http, https and mailto links with Gtk.show_uri_on_window, and nothing else (M5); a bare URL in the text is a link too (M6);
  • a rule as a GtkSeparator in the text, at a child anchor.

The colours come from the theme: the link colour, and a dimmed and a tinted colour made from the text colour, looked up again when the theme changes, so the dark theme works. The text can be selected and copied. The Import dialog uses a label: the same tokens make Pango markup, <b>, <i>, <s>, <tt> and <a href>. A web view would bring a browser engine, WebKitGTK, to show a README.

§7Implementation plan

Five steps, each one a commit with its tests, stopping for review after each.

  1. The parser. A new module, virtualbricks/markdown.py, with no GTK: the parser with its rules, parse(text), first_line(text), the plain text of the first line for the Projects list, and first_paragraph(text), the first paragraph that isn’t a heading. markdown-it-py joins the dependencies in pyproject.toml and in the README’s list of packages; its lowest version to be checked against Ubuntu 22.04’s package.
  2. The view. virtualbricks/gui/markdownview.py: MarkdownView, a read-only GtkTextView with set_markdown(text), its tags and theme colours, links and rules; and pango_markup(text) for labels.
  3. The places that only read. The Projects window: MarkdownView in the details, first_line in the list, which keeps its one line trimmed with …. The Import dialog: the first paragraph as Pango markup, in a label of at most four lines that ends with … (lines and ellipsize of GtkLabel).
  4. The Readme tab. The overlay of §6: the preview by default, the two floating icon buttons, and the syntax icon (M8). Switching to the preview renders the text of the editor; saving doesn’t change. The note of the New Project dialog, fixed.
  5. The documentation. virtualbricks-config(5): the README of a project is Markdown, with the syntax of §3; virtualbricks-archive(7): the README member says so; their HTML pages; the README of the sources.

§8Tests

  • tests/test_markdown.py: each rule of §3 gives its tokens; tables, pictures, HTML and indented lines stay text; lines stay lines; first_line and first_paragraph on headings, lists, empty and old READMEs.
  • tests/gui/test_markdownview.py: the text of the buffer and the tags at each place for a README with every element; a click on a link opens it and one on a file: link doesn’t; a rule is a separator; the colours follow a change of theme; pango_markup escapes < and &.
  • The windows: the Projects window’s rows and details; the Import dialog’s paragraph and its four lines; the Readme tab opening on the preview, the two buttons switching, the preview after an edit, the syntax icon only in the editor, and the saving unchanged.

As for the earlier changes, each new test is checked against the code it guards, broken on a copy.
