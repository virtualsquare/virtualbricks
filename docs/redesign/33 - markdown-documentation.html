One source for the documentation

The documentation is in four forms, each written by hand: the man pages in pandoc’s Markdown, their HTML twins, the guide in Mallard for Yelp, and the design pages in HTML. This page makes the documentation of Virtualbricks Markdown, built by one script into man pages, Mallard pages for Yelp and HTML, with one look for every HTML page it builds, so that each thing is written once. The reference is in Yelp too, as pages of its own. The design pages stay as they are.

§1At a glance

Sources
Markdown only, the flavour of pandoc that docs/man/ uses today: the guide in docs/guide/, the reference in docs/man/, as it is (§3, U4).
Outputs
Man pages of the reference, Mallard pages of the guide for Yelp, and HTML of both, written by one script, docs/build.py, into docs/built/ and committed, so that pip, Debian and the website need no pandoc (§3, U4).
Tools
pandoc 3.9 of pypandoc-binary, already pinned for the man pages, reads every page; its own writers make the man pages and the HTML; the Mallard comes from its syntax tree, written in Python. yelp-tools is no longer needed to build, only to check the Mallard, in the tests, when it is installed (U1, U2).
The guide
Yelp keeps its pages and their ids, F1 and help: as they are. A label of a window is written **Add Disk**, a menu path **Projects › Import…**; a link to the reference is a link to one of its pages, which Yelp shows itself (§4, U3).
The HTML
One template and one stylesheet, those of config-files.html, which the design pages share already, for the guide and the reference; one tree, installed and on the website, whose links work offline (§5).
Reference
Each man page’s Markdown is also a page of Yelp, in the guide’s Reference section, and a web page in place of its hand-written twin, with the keys as tables and the diagrams as SVG, as today (§6, U6, U8).
Design pages
As they are: HTML written by hand, published online, outside the build; new pages too (§7, U5 C).
Plan
Five steps on a branch: the guide in Markdown with nothing visible changed, the reference in Yelp, the HTML, the reference on the web, the website (§8).

§5The HTML

  • One stylesheet, docs/templates/style.css: the tokens, dark mode, masthead and contents of config-files.html, written once, which the HTML tree links. The design pages keep their own copies of it, as today.
  • A page of the guide: the way back to its sections of the index (“Virtualbricks Help › Your lab”), its title, its text, then See also, with the pages it names and those that name it, as Yelp does. A picture shrinks to the column and opens in full when clicked.
  • The index: each section lists its pages by their sort title, with their desc, two columns where the page is wide, as Yelp shows them. A new section, Reference, lists the five reference pages, in Yelp as in the HTML.
  • A reference page: the masthead of the twins (the name, the line of NAME, the version), the contents from the # headings, sticky at the left (§6).
  • Links stay inside the tree: the guide links command-line.html, not the website, so the HTML that Virtualbricks opens without Yelp works offline, and the website, which publishes the same tree, the same.
  • The names of the reference pages stay, and are their ids in Yelp too: config-files, command-line, control-protocols, archive-protocol, vbp-format, since the posts and the website’s /documentation/ link them.
