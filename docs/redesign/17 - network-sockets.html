§1At a glance

Types
--socket tcp:8765 and --socket ssl:8765:privateKey=FILE, beside unix:PATH, each with protocol=text or amp. The option can still be given more than once, and each socket goes on its own.
Where
On 127.0.0.1 unless interface= names another address (N4). Plain tcp stays on this machine; across the network, ssl (N3).
Token
~/.config/virtualbricks/token, made at the first start that needs it and kept, so that a client machine copies it once; tokenFile= names another (N1).
Proof
The token never crosses the wire. Each end proves that it knows it, with an HMAC over a random value of each end. A program that takes the port before Virtualbricks learns nothing from a client (N2).
Certificates
ssl always encrypts, and the client checks the certificate of Virtualbricks. With caCertsDir=FOLDER, each client shows a certificate that the folder trusts, in place of the token (N5).
Unix
Nothing changes: a unix socket is yours alone and takes neither a token nor a certificate.
Protocols
The text protocol gets a handshake before its greeting. AMP gets Challenge and Authenticate, and ampwire.authenticate() does both for a program.
Log
Each connection to tcp or ssl is logged with its address, and with the name of its certificate. Refusals are warnings.
--command
--socket tcp:8765 --command status on this machine; --socket ssl:lab.example:8765:caCertsDir=~/vb/lab --command status from another (N6). It sends its folder only to this machine.
pyOpenSSL
Twisted[tls] becomes a dependency. The Twisted package of every supported distribution already depends on pyOpenSSL (N7).
Plan
Four steps, a commit each, on a new branch mg/network-sockets from develop (§10).

§2Today

Page 16 made --socket take descriptions in the syntax of Twisted’s endpoints, each with its protocol. Only unix is accepted; tcp and ssl are known and refused (16 M6). A unix socket is 0600 in a folder that is yours, so only you and root can connect.

What a connection can do is what the console does. That includes event new e1 shell "…" and event start e1, which run a shell command as you (page 14). A port is a different kind of door: on 127.0.0.1, every user of this machine can knock, and so can a container that shares its network. Across the network, anyone who reaches the port can, and anyone on the way can read or change what passes. So a tcp or ssl socket has to know who connects before it answers anything. That is most of this page. The commands, dispatch.run(), the order of requests and the end of a connection stay as pages 15 and 16 made them.

§3The descriptions

They are Twisted’s, with the same meaning, except protocol and tokenFile, which are ours, and caCertsDir, which Twisted has only in its client descriptions (§5). Each file is a path: ~ is expanded, and a relative path is read from the folder where Virtualbricks starts.

Checks with the options

  • The files of ssl are read with the other options: the certificate and its key must load and match, and caCertsDir must hold at least one .pem certificate. A wrong file stops the start with a message, rather than a warning in the log once the project is open. They are read again when the socket opens.
  • The token file is checked if it is there (§4). One that isn’t there yet is made when the socket opens.
  • The same address and port twice are refused, whatever the types: tcp:8765 and ssl:8765 would both be 127.0.0.1 port 8765. Addresses that overlap, such as 0.0.0.0 and 127.0.0.1 on one port, are found when the second socket opens, and it goes without.

Who has each

A port has no lock file: the operating system gives it to one process. The first Virtualbricks that opens it listens there; another gets Address already in use, goes without that socket and logs it. Unlike the lock of a unix socket, a port doesn’t say which process holds it. The rest is as on page 16: each socket opens on its own once the project is open, and at the end each connection is closed after its last answer.

§4The token

  • The file. $XDG_CONFIG_HOME/virtualbricks/token, one line (N1). The first start with a tcp or ssl socket that needs a token makes it, with 32 random bytes of secrets written as 43 characters, mode 0600, and logs that it did. It stays, so the next start has the same token, and a client machine copies it once.
  • Another file. tokenFile=FILE names another, for a lab whose token you give to someone who shouldn’t have your usual one. Virtualbricks makes that file too, if it isn’t there. --command never makes one.
  • Never in the arguments. tokenFile= takes a file, not the token: the arguments of every process can be read by every user of the machine, with ps.
  • Checks. The file must be yours, and neither the group nor others may read it; otherwise it is refused with chmod 600 FILE in the message, as ssh does with its keys. Spaces and the newline at its ends don’t count. A token must have at least 16 characters, so that 1234, written by hand, is refused. --command checks the same.
  • A new token. Delete the file, or write another token in it, and start Virtualbricks again: it reads the file once, at start. Then copy it to the clients again.

The proof

Neither end sends the token (N2). On connecting, Virtualbricks sends a nonce, 32 random bytes in hex. The client answers with its own nonce and a proof: the HMAC-SHA256, under the token, of both nonces. Virtualbricks checks it with hmac.compare_digest and answers with its own proof, over the same nonces, which the client checks in turn:

  • A port taken first. Any user can open a free port of 127.0.0.1. Someone who opens 8765 while your Virtualbricks isn’t running gets, from --command, a proof over a nonce of their own, which opens nothing: the real Virtualbricks sends a new nonce each time. And --command stops there, since that end has no proof to give back.
  • Ten seconds. A connection that hasn’t proved itself in 10 seconds is closed. Before its proof, a connection can send only the proof; anything else is answered with an error, and the connection is closed.
  • A wrong proof gets the error Wrong token, and the connection is closed. The log warns, with the address.
  • Guessing. A token of 32 random bytes can’t be guessed one connection at a time, so there is no limit on attempts for now (§12).

§5Certificates

  • Always. ssl encrypts what passes, and the client checks the certificate of Virtualbricks: the client knows that it talks to the right machine, and nobody on the way reads the commands or changes them.
  • The certificate of Virtualbricks is privateKey and certKey, Twisted’s keywords. A client trusts it through caCertsDir=, a folder with the certificate itself or its authority; without it, through the authorities of its system, for a certificate from a public one.
  • Client certificates (N5). With caCertsDir=FOLDER, each client shows a certificate that one of the .pem files of the folder issued, or that is one of them. So the folder holds an authority of the lab, or the self-signed certificate of each client. A client without one, or with another, is refused during the TLS handshake, before a byte of it reaches Virtualbricks. There is no token then: the greeting comes right after the handshake.
  • Who it is. The log names each connection by the common name of its certificate: alice-laptop.
  • A client that goes. Remove its certificate from the folder and start Virtualbricks again, which reads the folder once, at start.
  • Twisted. Its server ssl: has no keyword for client certificates. Virtualbricks borrows caCertsDir from Twisted’s client descriptions, where it names the certificates that a client trusts, and builds the TLS options itself, with CertificateOptions(trustRoot=...).

Checked with Twisted 24.11 and pyOpenSSL 25 in the job’s folder, with certificates made as above: a client whose self-signed certificate was in the folder was let in, and its common name was there once the handshake completed; one with another certificate got unknown ca, and one without got certificate required. Python’s own ssl module checked the self-signed certificate of the server by its IP address, and refused it when given another certificate to trust.

§6The protocols

Text

On a socket that needs a token, the first line says so and carries the nonce. The greeting of page 15 comes once the proof is right, with the proof of Virtualbricks:

  • On a unix socket, and on ssl with client certificates, the greeting is the first line, as today.
  • protocol stays 1: the greeting and the requests don’t change, and the new first line comes only on the new types, which no client of today reaches.
  • A program computes the proof with the HMAC of its language. By hand, with socat or openssl s_client, openssl dgst -sha256 -hmac computes it.

AMP

Two commands and two errors join ampwire.py, with a function that runs the handshake for a program:

  • Before the proof, Hello and Run fail with TokenNeeded, which joins their errors. A program with the definitions of page 16 gets it as AMP’s UnknownRemoteError, still a failure. The names and arguments of both stay, so protocol stays 1.
  • A wrong proof fails with WrongToken, and the connection is closed. So do Challenge and Authenticate on a socket that takes no token, with a message that says so.
  • Ten seconds to prove, as on the text socket.
  • ampwire.py still loads no reactor and nothing of Virtualbricks: hmac and secrets are Python’s. It has its own copy of proof(), and a test checks that it gives what wire.proof() gives.
  • The program uses Twisted’s tls: client, which checks the name in the certificate; its client ssl: doesn’t. trustRoots is a folder of .pem files. With a client certificate, :certificate=…:privateKey=… joins the description, and there is no authenticate(). Checked with Twisted 24.11: that description reached a server that asked for a client certificate.
  • Over tcp on this machine: tcp:127.0.0.1:8766, then authenticate().

§7--command

  • The machine (N6). Twisted’s client form: tcp:HOST:PORT, or host= and port=. tcp:PORT alone is 127.0.0.1, so tcp:8765 is the same on both ends. interface= is refused with --command, with a message that shows host=.
  • The keywords of --command: host, port, protocol (text) and tokenFile; for ssl, also caCertsDir, the certificates it trusts for Virtualbricks, and privateKey and certKey, its own certificate, when Virtualbricks asks for one. Those are the keywords of Twisted’s client ssl:.
  • The token is that of tokenFile=, or the default file. It must be there, yours, and unreadable by others. --command sends only the proof, and checks the proof of Virtualbricks before it sends the command.
  • The folder. cwd goes with each request over unix, and over tcp or ssl when the other end is a loopback address. To another machine it isn’t sent, since its folders aren’t that machine’s: a relative path is read from the folder of that Virtualbricks, as for a request without cwd (15 Q6).
  • Waiting. 10 seconds to connect and prove. Then as long as the command takes, as today.
  • What it loads. Python’s socket, ssl, hmac and secrets; still neither Twisted nor pyOpenSSL. The exit statuses stay those of page 15: 2 when nothing answers the command, a refused token or certificate included.

§9The code and the tests

  • The description. Socket gets host, port, token_file and the files of ssl; path stays for unix. parse_socket(text, client=False) reads the listening form, and with client=True the form of --command. wire.TYPES becomes unix, tcp and ssl; wire.py still loads no Twisted.
  • The server. listen() keeps its lock and checks for unix, and for tcp and ssl calls listenTCP or listenSSL on the interface. Both protocols start in a state that waits for the proof when the socket has a token; the text protocol sends the first line, AMP refuses all but the two new commands. A callLater of 10 seconds closes a connection that doesn’t prove itself. An IHandshakeListener names the certificate once the TLS handshake is done. Control gets a name for the log in place of its path.
  • The client. client.connect() takes a Socket. It opens socket.create_connection, wrapped by ssl.create_default_context() with the certificates of caCertsDir and its own; then Connection runs the handshake when the first line asks for it.
  • The dependency. Twisted[tls]>=22.1 in pyproject.toml brings pyOpenSSL, service-identity and idna; .venv gets them. Only console/tls.py imports pyOpenSSL, when an ssl socket is described.

§11Decisions

QuestionOptionsDecided
N1 Where the token comes from

A A file in the config folder, ~/.config/virtualbricks/token, made at the first start that needs it and kept. tokenFile= names another. A client machine copies it once.

B A new token at each start, in the runtime folder. Only your processes on this machine can read it, and a client on another machine needs a new copy after each start.

C Only a file that you make and name with tokenFile=; Virtualbricks makes none.

 A
N2 How the token is checked

A Neither end sends it: each proves that it knows it, with an HMAC over a nonce of each end (§4). Whoever takes the port first learns nothing, and the client knows that the other end has the token. A program needs an HMAC, which every language has.

B The client sends it, as the first message: {"token": "…"}. Easier by hand, but whoever listens on the port gets it: on tcp, any user of the machine who opens the port before Virtualbricks.

 A
N3 Plain tcp across the network

A Refused: tcp listens on a loopback address only. Across the network, ssl, or ssh -L to a socket on the lab machine. On a network, anyone who can see the traffic reads the commands and their answers, and anyone who can change it can take over a connection after its proof.

B Allowed, and the log warns at start.

 A
N4 Where tcp and ssl listen without interface=

A 127.0.0.1, this machine. The network takes interface=0.0.0.0 or ::, written on purpose.

B Every address, as Twisted’s tcp:8765 does.

 A
N5 Client certificates on ssl

A With caCertsDir=, a certificate that the folder trusts, in place of the token. Without it, the token.

B With caCertsDir=, a certificate and the token, both.

C Always a certificate on ssl; the token is for tcp only.

 A
N6 How --command names the machine

A Twisted’s client form: tcp:HOST:PORT, or host=; tcp:PORT alone is this machine, so tcp:8765 works on both ends. interface= is refused with --command.

B The description that Virtualbricks listens on, with interface= as the machine to reach: tcp:8765:interface=192.0.2.7.

N7 pyOpenSSL

A A dependency: Twisted[tls] in pyproject.toml. The python3-twisted of every supported distribution already depends on python3-openssl and python3-service-identity, so nothing more is installed there; pip installs them with Virtualbricks.
