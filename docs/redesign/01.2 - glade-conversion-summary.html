§2Structure

Each module contains the class(es) that used the .ui file, with the same name, the original code and two new methods:

  • build_ui() creates every widget of the Glade file. A widget is an instance attribute only when it is needed after build_ui(): it is the root widget, a method of the class (or of its bases/subclasses) uses it, another object reads it (gui.window) or it is looked up by name (get_object("x"), the widget-name tables of the Qemu and Netemu panels). All the other widgets are local variables of build_ui(). get_object(name) returns None for them. Signals are connected at the end of build_ui(), like Gtk.Builder.connect_signals() did after loading.
  • get_root_widget() returns the main widget (window, dialog or panel).

The code of the original class is copied with the Gtk.Builder access replaced by attributes: self.w.x, self.get_object("x"), go("x") → self.x; BuilderHelper(...) + connect_signals() → self.build_ui(). get_object(name) is still available for the few lookups by computed name (go(param + "_check") in NetemuConfigController).

windows/base.py holds the Gtk.Builder-free base classes and the shared helpers, so that no module imports gui.py (it imports these modules, that would be circular):

  • Local widgets with a signal handler follow the schema too (their name is in the handler name); the other local widgets only use snake_case of the Glade id (tlbBricks → tlb_bricks).
  • Handlers are on_<widget>_<signal>: on_dialog_response, on_ok_button_clicked, on_bricks_view_row_activated.
  • The Gtk name property set in Glade is unchanged (NewBrickDialog reads it to know the brick type).
  • VBGUI.wndMain is now VBGUI.window; gui.py was updated. ImportDialog.assistant is now the widget itself (the property was removed); Freezer.wait_window is now Freezer.window.

§5How the Glade features are converted

  • Properties: passed to the constructor as keyword arguments, in Glade order (Gtk.Label(label=_("Name:"), xalign=0, ...)), enums/flags as Gtk.Align.START. Gtk.TreeViewColumn, Gtk.ListStore and widgets.List don't accept keyword properties: they use set_properties().
  • Packing: Gtk.Box → pack_start/pack_end(child, expand, fill, padding); a Box child without packing uses add(), like Gtk.Builder, that applies the box default expand. Gtk.Grid → attach(), Gtk.Notebook → append_page(page, tab_label), Gtk.Stack → add_titled()/add_named(), Gtk.Assistant → append_page() + set_page_*(), Gtk.Toolbar → insert(), Gtk.ButtonBox secondary children → set_child_secondary(). reorder_child() only where the Glade position differs from the packing order.
  • Dialog buttons: add_action_widget(button, Gtk.ResponseType.X) keeps the response ids. It packs the button at the end and aligns it to the baseline, so the Glade packing and valign are restored right after.
  • Tree views and combo boxes: columns, cell renderers and their add_attribute() mappings; list stores with their column types and rows.
  • Images: pixbufs are loaded by load_pixbuf("name.png") from virtualbricks/gui/data, the same file Gtk.Builder used, with a comment. Stock ids and icon names are unchanged.
  • Mnemonics and accelerators: labels keep _ and use_underline=True; the five menu accelerators of the main window (Ctrl+O, Ctrl+S, Ctrl+Q, Ctrl+P, F1) use add_accelerator() with a Gtk.AccelGroup added to window (wndMain in Glade).
  • Translatable strings: _("..."), domain virtualbricks.
  • Custom widgets from glade-catalog.xml (widgets.TreeView, widgets.ComboBox, widgets.List, widgets.CellRendererFormattable, widgets.CellRendererBrickIcon) are created from virtualbricks.gui.widgets and marked with a comment.
  • Placeholders: # TODO: empty Glade placeholder, nothing to create.
  • Deferred settings: radio groups whose leader is created later (join_group()), default and focus widgets (grab_default(), grab_focus()) and accelerators are set after the whole tree is built.
  • Signal handlers: the implementations come from the original classes. Stubs (with typed signature and data=None) only where no class defines the handler: the two unused files and _ConfirmDialog.on_ConfirmDialog_response (implemented by all its subclasses).

§6Verification

  • Widget tree: for every file, the tree built by build_ui() was compared with the one built by Gtk.Builder from the .ui file: types, all readable properties, packing (child) properties, children order, notebook tabs, tree columns and cells, list store contents, dialog response ids, assistant pages, accelerators, default and focus widgets. All 35 generated modules match. about.py differs only by the version string, set by your build_ui().
  • Signals: every <signal> of every Glade file is connected to a method that exists in the class.
  • Names: no widget attribute shadows a method or attribute of its class.
  • Behaviour: every class was constructed and shown (or its configuration panel built, including the Qemu one) with the same arguments using the original and the new class, with the same result. Name validation, radio buttons, sensitivity and response handlers were compared on a few dialogs; VBGUI starts and shows the main window.
  • Tests: virtualbricks.tests.test_gui run against the new classes gives the same result as the original (14 passed, 3 expected failures) after one change to its Readme stub, that fakes get_object("readme_textview"): the mixin now reads self.readme_textview.
  • pyflakes is clean on windows/.

Removed from virtualbricks/tests:

  • test_dialogs.py: the tests of UsbDevWindow (a class that doesn't exist at HEAD either) and of accumulate_data() (a helper only that test used); the other tests now use the classes of windows/.
  • test_gui.py takes the state classes from windows.base.

Unused Glade files (converted, then deleted with the rest)

  • commitdialog.ui: the class that loaded it (an older CommitImageDialog) is commented out in dialogs.py; commitimagedialog.ui replaced it. Only the UI is converted, as CommitDialog, with 5 TODO stubs.
  • networkcards.ui: not referenced by any code (the network cards are in qemuconfig.ui). Converted as NetworkCards, with 2 TODO stubs.

Both can probably be deleted together with their .ui file. Today: commitdialog.py went with the disk images redesign (609fb21); networkcards.py went with the panels redesign (ba4508c).

Differences from Gtk.Builder

  • Freezer (userwait.ui) loaded its file without a translation domain, so its two strings were never translated; they now use the virtualbricks domain.
  • Translations go through Python gettext.dgettext("virtualbricks", ...) instead of the C gettext used by Gtk.Builder, with the same domain as the gettext.install() in brickfactory.py.
  • GtkAssistant has no public accessor for its internal action area in GTK 3. Glade only sets default values on it (can_focus=False), so nothing is lost. A TODO comment marks the spot. The has_padding packing Glade set on it was rejected by GTK anyway (a critical warning when loading the .ui).
  • importdialog.ui has a toplevel image1 that nothing uses; it is not created (TODO comment in ImportDialog.build_ui()).
  • VBGUI now connects its signals at the start of __init__ (in build_ui()) instead of in the middle. None of its signals can fire during the steps in between.
  • gi.require_version("Gtk", "3.0") before the imports, like about.py: pycodestyle reports E402 for it.

glade-catalog.xml

  • TreeViewColumn is declared in the catalog but not defined in widgets.py and not used by any .ui file.
  • List objects declare a PyObject column in the Glade files; widgets.List always creates that single column, so the declaration is not repeated.

Existing issues, copied as they are

  • EventConfigController.on_action_treeview_key_press_event uses self.model, which doesn't exist (it raised AttributeError before too).
  • VBGUI.on_events_selection_changed uses self.__state_event_config, which is never set (no signal is connected to it).
  • QemuConfigController.on_icon_filechooser_file_set raises NotImplementedError.
  • virtualbricks.tests.test_dialogs.build_model() uses MODEL.keys()[0] (Python 2), so 3 tests of TestExportDialog error.
  • Some lines copied from gui.py are longer than 79 characters.
