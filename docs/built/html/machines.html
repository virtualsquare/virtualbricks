Virtualbricks Help › Each kind of brick

Virtual machines

A virtual machine is a brick that QEMU runs. Its settings have a section for each part of it: Machine, the QEMU program, the type of machine, its processors and its memory; Disks; CD-ROM and boot; Network; Display; Sound and USB; Kernel, to boot a kernel of your own; and Advanced.

The line at the top says which QEMU will run the machine, and its version. The lists of machine types, CPU models, sound cards and network cards are what that QEMU has. When the program isn't there, the line says so, and the lists have only the choices of the machine. A setting that this QEMU lacks says so under it, in the colour of warnings, and its section is marked at the left: the machine starts without it, and the Logs window says so.

The settings take effect when the machine starts again.

Machine

Program

The QEMU program, by its architecture, as x86_64 for qemu-system-x86_64: the list has those in the QEMU folder of the project, see Where Virtualbricks looks. One that isn't there shows as not installed. i386 by default.

Machine type

The type of machine that QEMU emulates, as q35 or virt; The default for the one of QEMU, which the list names. The programs of ARM, and that of RISC-V in QEMU 11, have no default: choose one, as virt, or the machine can't start.

CPU model

The processor that QEMU emulates; The default for the one of QEMU.

KVM

Run the machine with KVM, the virtualization of the processor of this computer, far faster than emulating it. Where KVM can't run, as without /dev/kvm or for a processor of another kind, QEMU emulates it all the same. Off by default.

Virtual CPUs

The number of processors of the machine, from 1 to 64; 1 by default.

Memory

The memory of the machine, in MiB, from 1 to 99999; 64 by default.

KVM shadow memory, Shadow memory

With KVM: the memory that KVM keeps for the page tables of the machine, in MiB, when the default of QEMU isn't enough. Off by default.

ACPI

Power management. Stop asks the system of the machine to shut down through ACPI: without it, the system doesn't hear it, and only Terminate or Kill stop the machine. On by default.

Disks

Add Disk adds a disk on the first free device: hda to hdd, the floppies fda and fdb, and mtdblock. Each disk chooses its image in a list of the images of the project, which says what each is and who uses it. The list also has Add an Existing Image…, New Empty Disk… and Manage Images…, which shows the Images tab.

How a disk uses its image

Private copy

The default. The machine writes its changes to a file of its own in the folder of the project, made at its next start, as vm1_hda.cow, and the image stays as it is. Several machines can share one image this way.

The image itself
The machine writes to the image.

The line under a disk says what it does. The menu of a disk has Save as a New Image…, which keeps the changes of the machine as an image of their own; Merge into the image, which writes them into it, and lists first what else uses it; Start Over from the image, which throws the changes away; Show in Files and Remove Disk. Saving and merging run in the background, with their progress, and can be stopped.

Changes

Forget the changes

The machine writes the changes to its disks in temporary files, forgotten when it stops: each start begins from the same disks. Off by default.

Virtio disks
Attach the disks as virtio devices, faster than those of a PC, for a system that has their driver, as Linux, which names them vda, vdb and so on. Off by default.

CD-ROM and boot

CD-ROM

What the CD-ROM holds: Nothing, the default; An image, a file as an .iso; or A drive of this computer.

Image

With An image: the image file. Type it, or choose it with the button beside it.

Drive

With A drive: the CD-ROM drive of this computer, as /dev/cdrom.

Boot from

The first place the machine boots from: The default, that of QEMU; The first disk; The CD-ROM; The floppy; or The network.

Network cards

Add Card adds a card after the others. The cards are in the order the machine sees them, the first one first, eth0 in the settings. The button at the end of a card removes it. Each card has:

Model

The network card that QEMU emulates, of those that this QEMU has; rtl8139 by default, or another one where QEMU lacks it.

MAC address

The address of the card on the network. A new card has a random one; the button beside it makes another.

Plugged into

What the card joins:

  • a switch of the lab, by its name;

  • The host only, on QEMU's user network: QEMU joins the machine to this computer, and through it to the networks this computer reaches, with no switch;

  • Other bricks plug into it: the card is a socket, and a wire can plug into it when the setting Plugs into machines of the project allows it, see The project;

  • Nothing: the card goes nowhere, and the machine can't start until you plug it in or remove it.

Display

No display

The machine has no screen at all: only its console, and its serial port. VNC and SDL window are then greyed. Off by default.

Standard VGA

A standard VGA card in place of the one of the machine. Off by default.

VNC, VNC display

Show the screen of the machine over VNC, on the display of that number, from 0 to 500; 1 by default. A VNC viewer connects to port 5900 and the number, as vncviewer localhost:1. Off by default.

SDL window

Show the screen in a window of SDL. Off by default.

Keyboard layout

The layout of the keyboard of the machine, two letters, as it or de; empty for that of QEMU.

Sound and USB

Sound card

None, the default; PC speaker; or one of the sound cards of this QEMU.

Audio driver

Where the sound goes on this computer, as the Settings window says: see This computer.

USB

Give the machine USB, and the devices below. Off by default.

USB devices

The USB devices of this computer, each with a switch that gives it to the machine. A device that the machine has and this computer hasn't shows as not on this host. QEMU runs as you: it needs the right to open the device.

Kernel

Boot a kernel

Boot a kernel of your own, not the one on the disks. Off by default.

Kernel

With Boot a kernel: the file of the kernel.

Initial ramdisk, Ramdisk

With Boot a kernel: load an initial ramdisk with the kernel, and its file.

Command line

The command line of the kernel, as console=ttyS0 root=/dev/vda1.

GDB, GDB port

Let GDB debug the machine, on that TCP port, from 1 to 65535; 1234 by default. In GDB, target remote localhost:1234. Off by default.

Advanced

Local time

Start the clock of the machine at the local time, not UTC, as Windows expects. Off by default.

Drift fix

Correct the drift of the clock of the machine, which a busy computer slows down. Off by default.

Serial socket

Connect the serial port of the machine to a socket, vm1_serial for vm1, in the folder of the sockets of the project, see virtualbricks-config(5); a program such as socat connects to it. Off by default.

Icon

A picture to show in place of the icon of a virtual machine, in the list and in the Topology tab.

The console of a machine

While the machine runs, Process › Open Control Monitor, in its menu, opens the monitor of QEMU in a terminal, the one of the Terminal setting. There you type the commands of QEMU, as info network.

Stop, suspend, resume

Stop asks the system of the machine to shut down. Suspend, under Process, saves the state of the machine in its first disk and stops it; Resume starts it again from there. Reset is the reset button of the machine.
